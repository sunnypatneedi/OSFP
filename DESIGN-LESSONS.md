# Design lessons — Open Software Factory Profile

Earlier standards and systems, what went wrong or what they got right, and what that means for OSFP. Every row has a public source. Where a row describes a design choice rather than a failure, it says so.

## Task grant

| Earlier standard or system | What went wrong, or what it got right | Source | Consequence for OSFP |
|---|---|---|---|
| Saltzer and Schroeder, 1975 | Got right: "Base access decisions on permission rather than exclusion", and "Every access to every object must be checked for authority" | [The Protection of Information in Computer Systems](https://web.mit.edu/Saltzer/www/publications/protection/Basic.html) | Deny what the grant does not list (`OSFP.AU.4`); confirm the task's authority before each side effect (`OSFP.AU.5`); an unknown status is not success (`OSFP.GE.5`) |
| The confused deputy, 1988 | A program that "serves two masters" and "carries some authority from each" cannot keep them apart | [Hardy, 1988](http://www.cap-lore.com/CapTheory/ConfusedDeputy.html) | A request, an instruction, a skill, or a tool listing is never a grant (`OSFP.AU.3`) |
| UHP 2026-10-19 | Got right: where the runtime supports per-tool restriction, a server "MUST enforce it as a hard block"; otherwise it conveys the restriction "as a standing instruction", and "MUST NOT overstate" enforcement. The fact stays inside the harness interface, though | [UHP harnesses §4.3](https://github.com/HarnessRouter/harnessrouter/blob/8a898e95f5c1/protocol/versions/2026-10-19/harnesses.md#43-disabled-tools) | The grant records `enforced` or `instruction` for each restriction, tool or otherwise (`OSFP.AU.7`) |
| HarnessRouter | Design choice: the host product keeps "auth, data, permissions, and workflow"; the runtime gets one authorized task | [HarnessRouter docs](https://harnessrouter.ai/docs/host-app-vs-runtime-agent) | OSFP is the host side of that split: the grant, and the confirmation before each side effect (section 7) |
| MCP 2026-07-28 | Design choice: a tool name is unique only within its server, and the server's own name "SHOULD NOT be relied upon for disambiguation" | [MCP Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) | A grant names each MCP server by an identifier the factory assigns, and each tool by its name (`OSFP.PF.2`) |
| OAuth 2.0 Rich Authorization Requests | Design choice: an authorization server must refuse "an object of known type but containing unknown fields", and `type` is required | [RFC 9396](https://www.rfc-editor.org/rfc/rfc9396) | A grant is its own record, because OSFP consumers ignore unknown fields (`OSFP.GE.4`); a factory may translate a grant for an OAuth server |
| Anthropic Managed Agents | Got right: the session is "the append-only log of everything that happened", and tokens are "never reachable from the sandbox where Claude's generated code runs" | [Anthropic Engineering](https://www.anthropic.com/engineering/managed-agents) | Records are never changed (`OSFP.GE.3`). Credentials never enter a model's input (`OSFP.AU.9`), and stay out of reach of code the model writes (`OSFP.AU.10`) |

## Outcome

| Earlier standard or system | What went wrong, or what it got right | Source | Consequence for OSFP |
|---|---|---|---|
| UHP 2026-10-19 | Got right: a repeated idempotency key must "not start a second execution", because "a retry that runs the work twice is worse than a slow answer". Keys "SHOULD be retained for at least 24 hours" | [UHP tasks §6](https://github.com/HarnessRouter/harnessrouter/blob/8a898e95f5c1/protocol/versions/2026-10-19/tasks.md#6-idempotency) | A re-send keeps its identity, and stops once the harness may have dropped it (`OSFP.OU.6`); the factory keeps the `attemptId` after the key expires (`OSFP.PF.1`) |
| UHP 2026-10-19 | Design choice: when the harness asks a person a question, "the task ends on the question", and the answer arrives as "a normal continuation" | [UHP tasks §3.2](https://github.com/HarnessRouter/harnessrouter/blob/8a898e95f5c1/protocol/versions/2026-10-19/tasks.md#32-asking-the-person) | One attempt spans a UHP task and the continuations that answer its questions (`OSFP.PF.1`) |
| A2A | `TASK_STATE_UNSPECIFIED` is "an unknown or indeterminate state". It is also the enum's zero value, and the state field is required | [A2A specification](https://a2a-protocol.org/v1.0.1/specification/); [a2a.proto](https://github.com/a2aproject/A2A/blob/3303592588e388e62e0f69f701af531d2f4e3991/specification/a2a.proto) | `unknown` travels as `TASK_STATE_INPUT_REQUIRED`, never as a terminal state, with the OSFP state in metadata (`OSFP.PF.3`, `OSFP.PF.5`); a missing state still reads as `unknown` (`OSFP.PF.4`) |
| Protocol Buffers | A field with implicit presence is "not serialized" when it holds its default value, and ProtoJSON omits it "by default", so a zero-value enum never reaches the wire | [Field Presence](https://protobuf.dev/programming-guides/field_presence/); [ProtoJSON Format](https://protobuf.dev/programming-guides/json/) | OSFP never sends `TASK_STATE_UNSPECIFIED` (section 11) |

## Verification evidence

| Earlier standard or system | What went wrong, or what it got right | Source | Consequence for OSFP |
|---|---|---|---|
| pytest and Bash | A run with no tests has its own exit code ("No tests were collected"). But a run where every test is skipped exits 0, so does a run where a filter deselects all tests but one, and "1 passed, 1 xfailed, 1 error" exits 1 (observed with pytest 9.0.2). A pipeline reports "the exit status of the last command" unless `pipefail` is set | [pytest exit codes](https://docs.pytest.org/en/9.0.x/reference/exit-codes.html); [Bash pipelines](https://www.gnu.org/software/bash/manual/html_node/Pipelines.html) | No pass without a success exit and an examined unit; skipped, deselected, and expected-failure units are not examined (`OSFP.EV.3`); capture the checking command's own exit status (`OSFP.EV.4`) |
| Frontier coding models (METR) | Models raised their scores "by modifying the tests or scoring code, gaining access to an existing implementation or answer that's used to check their work, or exploiting other loopholes in the task environment" | [METR, 2025](https://metr.org/blog/2025-06-05-recent-reward-hacking/) | Evidence records changed checks (`OSFP.EV.6`) and reachable withheld answers (`OSFP.EV.7`), and a consumer counts a pass only when the evidence rules both out (`OSFP.EV.11`). Neither model text nor evidence the attempt could have produced counts (`OSFP.EV.10`) |
| SLSA 1.2 build requirements | Got right: signing material "MUST NOT be accessible to the environment running the user-defined build steps" | [SLSA build requirements](https://slsa.dev/spec/v1.2/build-requirements) | Evidence the attempt could have produced or altered is not evidence (`OSFP.EV.10`) |
| in-toto Attestation | Design choice: the Statement is predicate-agnostic, and `gitTree` and `dirHash` can digest "arbitrary trees". `dirHash` covers regular files only | [Statement v1](https://github.com/in-toto/attestation/blob/v1.2.0/spec/v1/statement.md); [DigestSet](https://github.com/in-toto/attestation/blob/v1.2.0/spec/v1/digest_set.md) | OSFP defines a predicate, not a new envelope, and names the checked tree by one of those digests (`OSFP.EV.1`) |
| SLSA Verification Summary Attestation | Design choice: a verification summary records the verifier's result together with the digest of each attestation it read (`inputAttestations`) | [SLSA 1.2 VSA](https://slsa.dev/spec/v1.2/verification_summary) | A verdict references the evidence it reviewed, and changes no check's status (`OSFP.EV.12`) |

## Progress

| Earlier standard or system | What went wrong, or what it got right | Source | Consequence for OSFP |
|---|---|---|---|
| Linux watchdog timer | Got right: "A Watchdog Timer (WDT) is a hardware circuit that can reset the computer system in case of a software fault". The timer does not depend on the software it watches | [The Linux Watchdog driver API](https://docs.kernel.org/watchdog/watchdog-api.html) | The supervisor's timer runs in a process separate from the one that runs the attempt (`OSFP.PR.2`) |
| DeepSeek Harness super-agent design (an English machine translation that describes ideas, not shipped features) | A persistent system "needs an independent Control Loop outside the main system"; in chat channels, "notify people only when a decision or sign-off is needed" | [DeepSeek Harness, 2026](https://x.com/DeepSeekHarness/status/2116857257245987236) | The same idea as the watchdog (`OSFP.PR.2`). OSFP does not adopt the alerting norm: when to alert a person is a product decision, not the meaning of a record |
| Kubernetes Jobs and CronJobs | Design choice: a Job past its deadline becomes "Failed with reason: DeadlineExceeded"; a CronJob skips a Job that misses its starting deadline and counts it as failed | [Jobs](https://kubernetes.io/docs/concepts/workloads/controllers/job/); [CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/) | OSFP stops the attempt too (`OSFP.PR.3`), but records what it can establish instead of "failed", and reports a missed start as `missed` (`OSFP.PR.4`) |
| CloudEvents 1.0.2 | Design choice: the `time` attribute is optional, and "`source` + `id`" must be unique for each distinct event | [CloudEvents 1.0.2](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md) | The progress record names its own event and time (`OSFP.PR.7`), so it means the same thing with or without the envelope |
| OpenTelemetry GenAI conventions | The agent-span conventions carry "Status: Development", so attribute names can still change | [Agent spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/da2b5736d7a3533fd7d324872b77e4c2eabbe392/docs/gen-ai/gen-ai-agent-spans.md) | OSFP recommends OpenTelemetry but does not depend on its attribute names (`OSFP.PF.6`) |

## How the standard is made

| Earlier standard or system | What went wrong, or what it got right | Source | Consequence for OSFP |
|---|---|---|---|
| OMBS, an earlier standard by the same maintainer | A pull request titled "do not merge before 2026-08-26" merged on 2026-07-28, so the announced comment window never ran; governance named a body that did not exist | [OMBS CHANGELOG, lines 59-62](https://github.com/sunnypatneedi/ombs/blob/e99956f/CHANGELOG.md#L59-L62) | GOVERNANCE.md names only people and bodies that exist, and every release stays a draft until outside readers and an outside implementer exist |
| OMBS | The checker's summary line claimed more coverage than it checked; prose and data diverged silently because the check compared presence, not text | [OMBS CHANGELOG, line 42](https://github.com/sunnypatneedi/ombs/blob/e99956f/CHANGELOG.md#L42) and [lines 130-132](https://github.com/sunnypatneedi/ombs/blob/e99956f/CHANGELOG.md#L130-L132) | OSFP's checker requires each rule's text to equal the text that defines its ID, and fails a second definition, a missing text, or a restatement with key words. It took two tries: before publication, one review broke a version that searched the whole document, and a second broke a version that tested containment. The conformance table and the references are compared with the data the same way |
| ALTO, an earlier standard by the same maintainer | Its governance section proposed a "Validator tool (CLI + web)"; the repository at that commit has no validator | [ALTO spec, line 710](https://github.com/sunnypatneedi/alto/blob/51ea19b/spec/ALTO-v0.1.md#L710) | OSFP publishes its checks, a self-test that proves each check can fail, and the CI that runs them, in its first draft |
