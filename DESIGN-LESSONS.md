# Design lessons — Open Software Factory Profile

Earlier standards and systems, what went wrong or what they got right, and what that means for OSFP. Every row has a public source. Where a row describes a design choice rather than a failure, it says so.

| Earlier standard or system | What went wrong, or what it got right | Source | Consequence for OSFP |
|---|---|---|---|
| UHP 2026-10-19 | Got right: a server must enforce a disabled tool, or convey it "as a standing instruction", and "MUST NOT overstate" enforcement. The fact stays inside the harness interface, though | [UHP harnesses §4.3](https://github.com/HarnessRouter/harnessrouter/blob/8a898e95f5c1/protocol/versions/2026-10-19/harnesses.md#43-disabled-tools) | The grant records `enforced` or `instruction` for each restriction, tool or otherwise (`OSFP.AU.5`) |
| UHP 2026-10-19 | Got right: a repeated idempotency key must "not start a second execution", because "a retry that runs the work twice is worse than a slow answer". Keys "SHOULD be retained for at least 24 hours" | [UHP tasks §6](https://github.com/HarnessRouter/harnessrouter/blob/8a898e95f5c1/protocol/versions/2026-10-19/tasks.md#6-idempotency) | A re-send keeps its identity (`OSFP.OU.8`); the factory keeps attempt identity after the key expires (`OSFP.PF.1`) |
| HarnessRouter | Design choice: the host product keeps "auth, data, permissions, and workflow"; the runtime gets one authorized task | [HarnessRouter docs](https://harnessrouter.ai/docs/host-app-vs-runtime-agent) | OSFP is the host side of that split: the grant and its checks (section 7) |
| A2A | `TASK_STATE_UNSPECIFIED` is "an unknown or indeterminate state". It is also the enum's zero value, and the state field is required | [A2A specification](https://a2a-protocol.org/latest/specification/); [a2a.proto](https://github.com/a2aproject/A2A/blob/cfc9d34bc41e368827eb6446d31f912e44f795c5/specification/a2a.proto) | `unknown` maps to `TASK_STATE_UNSPECIFIED`, never to a terminal state (`OSFP.PF.2`); a missing state reads as `unknown` (`OSFP.PF.5`) |
| Protocol Buffers JSON | Fields that hold their default value "are omitted by default in JSON output", so a zero-value enum can vanish in transit | [ProtoJSON Format](https://protobuf.dev/programming-guides/json/) | A factory that reports `unknown` emits the state field anyway (`OSFP.PF.6`) |
| OAuth 2.0 Rich Authorization Requests | Design choice: an authorization server must refuse "an object of known type but containing unknown fields", and `type` is required | [RFC 9396](https://www.rfc-editor.org/rfc/rfc9396) | A grant is its own record, because OSFP consumers ignore unknown fields (`OSFP.GE.3`); a factory may translate a grant for an OAuth server |
| Saltzer and Schroeder, 1975 | Got right: "Base access decisions on permission rather than exclusion", and "Every access to every object must be checked for authority" | [The Protection of Information in Computer Systems](https://web.mit.edu/Saltzer/www/publications/protection/Basic.html) | Deny what the grant does not list (`OSFP.AU.3`); check the latest grant before each side effect (`OSFP.AU.4`); an unknown status is not success (`OSFP.GE.4`) |
| The confused deputy, 1988 | A program that "serves two masters" and "carries some authority from each" cannot keep them apart | [Hardy, 1988](http://www.cap-lore.com/CapTheory/ConfusedDeputy.html) | A request, an instruction, a skill, or a tool listing is never a grant (`OSFP.AU.2`) |
| OpenTelemetry GenAI conventions | The agent-span conventions carry "Status: Development", so attribute names can still change | [Agent spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md) | OSFP recommends OpenTelemetry but does not depend on its attribute names (`OSFP.PF.4`) |
| in-toto Attestation | Design choice: the Statement is predicate-agnostic, and `gitTree` and `dirHash` can digest "arbitrary trees" | [Statement v1](https://github.com/in-toto/attestation/blob/main/spec/v1/statement.md); [DigestSet](https://github.com/in-toto/attestation/blob/main/spec/v1/digest_set.md) | OSFP defines a predicate, not a new envelope, and names the checked tree by one of those digests (`OSFP.EV.1`) |
| Kubernetes Jobs and CronJobs | Design choice: a Job past its deadline becomes "Failed with reason: DeadlineExceeded"; a CronJob skips a Job that misses its starting deadline and counts it as failed | [Jobs](https://kubernetes.io/docs/concepts/workloads/controllers/job/); [CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/) | OSFP stops the attempt too (`OSFP.PR.3`), but records what it can establish instead of "failed", and reports a missed start as `not-run` (`OSFP.PR.8`) |
| OMBS, an earlier standard by the same maintainer | A pull request titled "do not merge before 2026-08-26" merged on 2026-07-28, so the announced comment window never ran; governance named a body that did not exist | [OMBS CHANGELOG, lines 59-62](https://github.com/sunnypatneedi/ombs/blob/e99956f/CHANGELOG.md#L59-L62) | GOVERNANCE.md names only people and bodies that exist, and every release stays a draft until outside reviewers exist |
| OMBS | The checker's summary line claimed more coverage than it checked; prose and data diverged silently because the check compared presence, not text | [OMBS CHANGELOG, line 42](https://github.com/sunnypatneedi/ombs/blob/e99956f/CHANGELOG.md#L42) and [lines 130-132](https://github.com/sunnypatneedi/ombs/blob/e99956f/CHANGELOG.md#L130-L132) | OSFP's checker compares each rule's text with the one line that defines its ID, and fails a second definition or a restatement with key words. An earlier version of this checker searched the whole document. Before OSFP's first commit, a reviewer swapped two rules' text in a copy, and that version still passed |
| ALTO, an earlier standard by the same maintainer | Its governance section proposed a "Validator tool (CLI + web)"; the repository at that commit has no validator | [ALTO spec, line 710](https://github.com/sunnypatneedi/alto/blob/51ea19b/spec/ALTO-v0.1.md#L710) | OSFP ships its checker, and its CI, in its first commit |
| DeepSeek Harness super-agent design (an English machine translation that describes ideas, not shipped features) | A persistent system "needs an independent Control Loop outside the main system"; in chat channels, "notify people only when a decision or sign-off is needed" | [DeepSeek Harness, 2026](https://x.com/DeepSeekHarness/status/2116857257245987236) | The supervisor's timer runs outside the loop (`OSFP.PR.2`). Alerts go out only for decisions and sign-offs (`OSFP.PR.7`); the source states that norm for chat, and OSFP applies it to every alert |
| Anthropic Managed Agents | Got right: the session is "the append-only log of everything that happened", and tokens are "never reachable from the sandbox where Claude's generated code runs" | [Anthropic Engineering](https://www.anthropic.com/engineering/managed-agents) | Records are never changed (`OSFP.GE.5`). Credentials never enter a model's input (`OSFP.AU.7`), and stay out of reach of code the model writes (`OSFP.AU.8`) |
| pytest and Bash | A run with no tests has its own exit code ("No tests were collected"), but a run where every test is skipped exits 0 (observed with pytest 9.0.2); a pipeline reports "the exit status of the last command" unless `pipefail` is set | [pytest exit codes](https://docs.pytest.org/en/stable/reference/exit-codes.html); [Bash pipelines](https://www.gnu.org/software/bash/manual/html_node/Pipelines.html) | No pass without an examined unit, and a skipped unit is not examined (`OSFP.EV.3`); capture the checking command's own exit status (`OSFP.EV.4`) |
| Frontier coding models (METR) | Models raised their scores "by modifying the tests or scoring code, gaining access to an existing implementation or answer that's used to check their work, or exploiting other loopholes in the task environment" | [METR, 2025](https://metr.org/blog/2025-06-05-recent-reward-hacking/) | Evidence records changed checks (`OSFP.EV.6`) and reachable answers (`OSFP.EV.12`), and consumers do not count either as a pass (`OSFP.EV.11`). Model text never counts as evidence (`OSFP.EV.7`) |
